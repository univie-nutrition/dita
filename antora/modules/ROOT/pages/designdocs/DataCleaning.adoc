= Data Cleaning
:includedir: includes

Typically with surveys, data will be entered incorrectly by interviewers 
or issues with recipes are discovered only *after* interviews had been conducted.
Hence it is likely that respondent and consumption data will need correction as a post processing step.

_Dita_ implements an interview-set transformer that corrects interview data based on uploaded correction files.
Those correction files have the `Correction24` structure:

== Respondent Correction

Allows to correct defect data entered during interview such as _Respondent-Id_, _Sex_ or _Date of Birth_.
Also allows to remove interviews from respondents that later withdrew.

[source,yaml]
.Fixing respondent-id typo
----
respondents:
- alias: "EB9999"
  newAlias: "EB_9999"
----

[source,yaml]
.Fixing respondent-data
----
respondents:
- alias: "EB_9999"
  dateOfBirth: 1999-11-22
  sex: MALE
----

[source,yaml]
.Respondent withdrawal
----
respondents:
- alias: "EB_9999"
  withdraw: true
----

== Consumption Correction

=== Food

Correcting food consumptions that have no identifier, only a name.

[source,yaml]
.Fixes food with missing identifier
----
foodByName:
- name: "Maiswaffeln"
  sid: "at.gd/2.0:food/02423"
----

=== Composite

Correction of composite consumptions supports:

* Renaming of the composite entry `rename`
* Update of the composite's group `groupSid`
* *ADD* Ingredient: `sid`, `amountGrams`, `facets`
* *DELETE* Ingredient: `sid`, `facets`

After application all ingredient amounts are re-calculated such that the composite's total amount consumed stays the same.

`facets` is a `SemanticIdentifierSet`. In YAML an empty set is `facets: ""` and a non-empty set is a list of identifiers, e.g. `facets: ["at.gd/2.0:facet/001"]`.

[source,yaml]
.Delete and add ingredients
----
composites:
- coordinates: 
    sid: "at.gd/2.0:recp/00514"
    respondentId: "EB_9999"
    interviewOrdinal: 1
    mealHourOfDay: "13:00:00"
    source: "wave1/Interview-12345.xml"
  deletions: 
  - sid: "at.gd/2.0:food/02280"
    facets: ""
  additions: 
  - sid: "at.gd/2.0:food/01399"
    amountGrams: 302.72
    facets: ""
  - sid: "at.gd/2.0:food/01581"
    amountGrams: 6.05
    facets: ""
----

[source,yaml]
.Rename only
----
composites:
- coordinates: 
    sid: "at.gd/2.0:recp/00514"
    respondentId: "EB_9999"
    interviewOrdinal: 1
    mealHourOfDay: "13:00:00"
    source: "wave1/Interview-12345.xml"
  rename: "New Name"
  deletions: [] 
  additions: []
----

== Consumption Identification

A composite entry is identified by `Coordinates`:

* `sid` : SemanticIdentifier of the recipe
* `respondentId`
* `interviewOrdinal`
* `mealHourOfDay`
* `name` : optional, for ad-hoc or modified composite entries
* `source` : path of the interview source file

WARNING: This may still not be enough information to nail down a unique entry. In that case corrections are applied to *all* entries that match the coordinates.

NOTE: Uploading new interview data may render existing coordinates invalid.

== Working with multiple Correction Files / Steps

Multiple files are merged into one `Correction24` for post processing.

A `Correction24` must not contain coordinate duplicates, because application order matters and is not commutative. Use a sequence of `Correction24` steps for ordered changes.

A minimal file always contains the three top level keys:

[source,yaml]
.Minimal Correction24
----
respondents: []
foodByName: []
composites: []
----

== Generating corrections from FoodDescriptionModel Changes

Recipe changes can be converted automatically into a `Correction24` template.
This is useful when the Food Description Model (FDM) changes after interview
data has already been collected.

`FdmDiffFactory` compares previous and current FDM versions.
`CorrectionTemplateFactory` combines the diff with existing `Record24.Composite` entries and creates a `Correction24`.

Ingredient key = `recipeSid + foodSid + facet hash`. Order (within a recipe) is irrelevant.

Changes detected:

* key only in old → DELETE
* key only in new → ADD
* same key, changed relative mass → DELETE + ADD
* facets changed → DELETE + ADD

Amounts are compared in permille relative mass. The factory emits `Addition` with the *new absolute amount in grams* projected from the relative change; post processing will re-normalise to keep the composite total constant.

Example amount change:

[source,yaml]
.Amount change generated as delete + add
----
composites:
- coordinates:
    sid: "at.gd/2.0:recp/00514"
    respondentId: "EB_9999"
    interviewOrdinal: 1
    mealHourOfDay: "13:00:00"
    source: "wave1/Interview-12345.xml"
  deletions:
  - sid: "at.gd/2.0:food/01581"
    facets: ""
  additions:
  - sid: "at.gd/2.0:food/01581"
    facets: ""
    amountGrams: 6.05
----

The entire _Composite Correction_ process:

.Correction template generation from FDM changes

newFdm --> fdmDiffFactory

fdmDiffFactory -> diff : creates

diff --> templateFactory : recipe changes
records --> templateFactory : composite entries

templateFactory --> correction : creates

correction -> review : optional
review -> processing : approved corrections
correction -> processing : direct application

note bottom of templateFactory
  Matches recipes and consumption entries
  using Coordinates.
  Ingredient changes are represented as
  deletions and additions.

@enduml
